      Get started developing

      From nothing to your first mod built, linked and checked: about half an hour, most of it installing a compiler.

      What you need

      • Python 3.9 or newer and git. elekloader itself has no other dependencies.
      • The stock OS file for your device, from Elektron's support pages: the same file this page asks for. elekloader recognises each release by its hash.
      • The cross compiler, for a mod with code. On the Digitakt mk1 and the Digitone mk1 that is m68k binutils and gcc: on Debian or Ubuntu apt install binutils-m68k-linux-gnu gcc-m68k-linux-gnu; on Windows, the same inside WSL; on a Mac, with Homebrew, brew install m68k-elf-binutils m68k-elf-gcc, then export ELEKLOADER_CROSS=m68k-elf- (Homebrew's tools have that prefix). A mod that only changes a byte or two needs none.
      • Optional: digiemu, to run and check your build without a unit (Test before you flash).

      Your first mod

      1. Get the code and check it runs: 
        git clone https://github.com/irpina/elekloader
cd elekloader
python tests/test_units.py
      2. Copy the template, a complete mod that draws a small square in the corner of every screen. For the Digitakt II start from examples/hello-marker-dt2, for the Octatrack hello-marker-ot, for the Models hello-marker-model: 
        cp -r examples/hello-marker my-mod
      3. Give it your own id in my-mod/mod.json (lowercase; it also prefixes your global symbols), then build it and the core for your device: 
        python -m elekloader.sdk.build my-mod --stock Digitakt_OS1.53.syx
python -m elekloader.sdk.build mods/core --stock Digitakt_OS1.53.syx
        Each prints BUILT and the .elemod it wrote (in the folder's out/).
      4. Check it the way every build is checked, then make a firmware file from it: 
        python -m elekloader.lint my-mod/out/my-mod-1.0.elemod --stock Digitakt_OS1.53.syx --with mods/core/out/core-4.0.elemod
python -m elekloader.patch --stock Digitakt_OS1.53.syx --mod mods/core/out/core-4.0.elemod --mod my-mod/out/my-mod-1.0.elemod --out test.syx --version TEST
        The file names are the ones the build printed. Or skip the command line: drop your .elemod on this page's Build view with your stock file.

      The rules in short

      • Subscribe, don't patch. If the core has an event for what you need, use it. If it doesn't and another mod could want the same thing, that's a core event to add: What is a core mod?
      • Ship no firmware. Call firmware routines by address; never copy Elektron's code into your sources.
      • One namespace. Prefix your global symbols with your mod's id, and keep the rest static.
      • Only the main OS changes, so the stock OS file always gets a unit back.

      The whole guide, with every command's expected output and every refusal message with its fix: Adapting your mod. Working with a coding agent? Point it at AGENTS.md: it has the rules, the commands and what "done" means.

      Contribute

      What is a core mod?

      The one mod every build has, and the reason mods from different people combine.

      Without it

      A mod changes the stock firmware at the places it needs: it replaces an instruction with a jump to its own code. Two mods that need the same place can't both have it, so they can't be in one build, and every mod has to find all its places again for each new OS version.

      With it

      The core owns the shared places once, for every mod, and offers them as:

      • Events a mod subscribes to: the UI tick, the screen, keys and encoders, SETTINGS, the audio render, MIDI, and more on each device. A handler can also take what it sees (a key, a CC) so the stock firmware doesn't.
      • Tables other mods add entries to: the Digitakt's SRC machines, the Digitone's Mod Menu.
      • Firmware exports: named firmware routines and variables (fw_…), so a mod that uses only those builds for every OS version the core supports without a port of its own.

      It also copies every mod's code into RAM when the unit boots, and gives the mods their share of it. Every linkable mod needs exactly one core for its device, and builds pick it for you.

      Companions

      A group of places only one kind of mod uses has a companion beside the core: machine-pages draws the Digitakt's SRC and LFO pages for machine mods, machines plays a machine mod's voice on the Digitone, and seq-events turns the sequencer's steps into events. The to-do list counts them as core.

      Versions

      Each core keeps everything the one before it had, so a mod built for an older core links with the newest, and a build takes the newest: core 4.x on the Digitakt mk1, core-dn1 4.x on the Digitone mk1, core-ot 0.3.x on the Octatrack. The Digitakt II, the Analog Rytm MKII and the Models have early cores (the tick, the screen, keys and encoders) with a lot left to add.

      Growing it

      Every event the core has came from a mod that needed it. When yours needs something the core lacks, build that part in the core's shape, in a file of its own, and open a pull request that moves it into the core: Growing the core says how. The to-do list is every place a mod still patches itself: each one a core event waiting to be written.

      Contribute

      Your first pull request

      Taking an entry from the to-do list to the leaderboard. You don't need to ask first, and a draft that says what it couldn't finish is a fine start.

      1. Pick an entry from the to-do list. A core event means the core has nothing there yet; move onto the core means a mod can use what the core already has (that change goes to the mod's own repository, and its shop update here is where you claim it).
      2. Open a draft pull request early, on irpina/elekloader, with a plain line in its description naming the entry: 
        Claims: digitakt-mk1@1.53:0x400d553e
        Others then see it's taken. Several ids on one line are fine.
      3. Build it in the core's shape: a file of its own in the core's folder, the core's names (ev_…, core_…, fw_…), the handler written down over the code, the unit behaving exactly as stock when no mod subscribes, and the address on every OS version the core supports. Growing the core has the checklist.
      4. Show it works: say in the pull request which tests ran (python tests/test_units.py always; the others need stock files), what you checked in digiemu or on a unit, and, best of all, a mod rebuilt on your event without its own patch.
      5. Mark it ready. A maintainer reviews and merges it, and the next build of this page puts you on the leaderboard, one point for each entry you claimed. The first merged claim on an entry takes it.

      A Claims: line inside a code block, a comment or a quote is an example and claims nothing. More in Claiming an entry.

      Test before you flash

      You can build, run and check most of it without a unit, and a unit always comes back.

      Every build is checked

      Before it writes a file, elekloader refuses any build that would change the bootloader, put two mods on the same bytes, or run out of the mods' RAM. python -m elekloader.lint runs the same checks on your mod alone, with the reason for each refusal.

      In an emulator

      digiemu runs the real firmware of the Digitakt mk1, the Digitone mk1, the Model:Cycles and the Model:Samples on Windows and on Apple silicon Macs, with a clickable front panel and live audio. You bring Elektron's file, as here.

      • Check firmware… takes your build's .syx and compares it with stock: it boots it, drives it through the screens and the sequencer, and ends with PASS or FAIL and the reasons.
      • Add your build as a firmware of its own to play it from the panel, or from a script with digiemu-console.exe --add FILE.syx.

      The Octatrack, the Digitakt II and the Analog Rytm MKII aren't emulated: there, test on a unit.

      On a unit

      Send your .syx with Elektron Transfer like any OS update (how to flash). The bootloader is never changed, so the stock OS file always gets the unit back: on a Digitakt mk1, Digitakt II or Digitone mk1, hold FUNC while powering on and press TRIG 4 for OS UPGRADE, then send the stock file; on an Octatrack, hold FUNC and press TRIG 3, and send it over 5-pin MIDI (recovery).

        About elekloader

        Nothing is uploaded. Your stock OS file and your mods stay in this browser tab; the build runs here, in Python compiled to WebAssembly. No firmware is hosted on this site: you bring Elektron's file. elekloader is an independent project, not affiliated with, endorsed by or supported by Elektron, and flashing custom firmware is at your own risk.
